# I2026051002 AI 原生工作原则

## 背景

用户在围绕 PR145 的讨论中指出：AI 做计划时容易默认采用“过渡”“兼容”“分步骤”等人工编码时代的工作方式。人工的上下文长度很长、长期记忆稳定，但执行效率较低，因此分步、阶段化和兼容式推进适合人的思维与协作方式。AI 的特点相反：执行效率高，但上下文长度有限、长期记忆可靠性差、跨会话容易产生幻觉。因此，AI 不应机械照搬人类时代的软件推进方式，而应具备对自身能力边界的觉悟，把适合 AI 的工作原则显式纳入系统提示词。

这条规则不是只约束 Snail Shell 的某个项目 stage，也不是某个角色的研发偏好，而是所有 AI 在规划、设计和实施时都应遵守的基础判断契约。

## 目标

1. 在 AI 基础提示词中沉淀“AI 原生工作原则”。
2. 明确 AI 不能默认把过渡、兼容、分步拆分当作更安全或更正确的方案。
3. 明确选择一次性整体改造、分步推进、兼容保留或过渡方案时，必须基于系统边界、上下文承载能力、验证能力和回滚风险判断。
4. 同步 `AGENTS.md` 与 `.meta/prompts/`，保持双线规则一致。

## 非目标

1. 不禁止所有分步实施。
2. 不禁止必要的兼容、迁移或过渡方案。
3. 不修改知识飞轮实现计划文档；本次规则沉淀进入长期入口和当前 feature 文档，不改写其他 feature 的交付记录。
4. 不实现代码、数据库或 UI 改动。

## 设计

### 规则归属

本规则归入 `.meta/prompts/base/P0004-AI判断与责任契约.md`，原因是它描述的是所有 AI 都应具备的自我判断边界：AI 必须根据自身上下文短、长期记忆弱、执行效率高的能力结构选择工作方式，而不是把人类协作中的默认做法当作天然正确。

不归入 `Implementation Snail / Development 行动手册`，因为该规则不只适用于研发迭代阶段，也适用于文档治理、检视、计划、知识治理和后续所有 AI 调用场景。

### 规则内容

规则要点：

1. AI 制定计划时必须显式考虑自身能力结构。
2. 分步、过渡和兼容不是默认正确的工程美德；它们只在确有外部使用者、数据迁移、线上风险、评审承载或回滚需要时成立。
3. 如果系统边界清晰、可验证、改造范围可一次性装入当前上下文，一次性完成正确模型通常比留下跨会话隐含状态更适合 AI。
4. 如果完整改造超出当前上下文或验证能力，应拆分为语义闭合的垂直切片，而不是按人类习惯拆成长期依赖记忆的半成品过渡层。
5. 拆分方案必须说明每一步的独立完成定义、后续依赖和防止遗忘的持久记录。

### 双线同步

`AGENTS.md` 当前通用原则中已有“独立判断”和“严禁盲目追求最小增量改动”。本次在同一通用原则区域增加 AI 原生工作原则摘要，与 `.meta/prompts/base/P0004-AI判断与责任契约.md` 保持语义一致。

## 风险与决策记录

1. 决策：不把规则写成“禁止分步”。原因是分步、兼容和过渡在存在真实外部约束时仍然必要；问题在于 AI 不能默认照搬人类时代的分步偏好。
2. 决策：强调“语义闭合的垂直切片”。原因是 AI 跨会话记忆弱，若拆成半成品过渡层，后续会话容易忘记隐含状态并在错误模型上继续建设。
3. 决策：本次不修改 PR145 的 feature 文档。原因是 PR145 属于独立 feature，本次新规则应沉淀到长期入口和当前 feature 文档，避免用当前 PR 改写其他 feature 的交付记录。
