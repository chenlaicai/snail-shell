# F2026050704 首页 UI 信息架构重设计

## 背景

当前首页把 Snail Shell 品牌栏固定为独立横向顶栏，占用了整页高度预算；一级目录“项目管理”“知识中心”被放在左侧项目侧栏中部，层级上像项目管理的子内容，不符合全局目录的使用直觉。一级目录未来还会增加，但它们不是高频操作，不应长期占用大块内容空间。

用户明确提出：系统图标与名称不应占用一整行；一级目录应更符合上下层级直觉、占用更小空间；切换一级目录后页面应进入该目录内容，不应混杂展示其他同级目录内容。

## 目标

1. 将系统图标、系统名称和一级目录整合进低占用的全局导航区域，释放原固定顶栏空间。
2. 将一级目录从项目侧栏中移出，使其成为真正的全局目录入口。
3. 切换“项目管理”和“知识中心”时，只展示当前目录相关的页面结构，避免同级目录内容混杂。
4. 保持现有项目、Feature、Conversation、知识中心、Inspector 等功能入口可用。
5. 保持桌面与移动端均可访问主要入口。

## 非目标

1. 不重做 Conversation 消息流、右侧 Inspector 内容或知识中心内部数据模型。
2. 不新增新的一级目录，只为未来目录扩展预留导航结构。
3. 不引入新的前端框架、构建链路或设计系统依赖。
4. 不改变后端 API、数据模型和阶段工作流。

## 设计

首页调整为三层结构：

1. 全局 rail：承载紧凑品牌标识、一级目录入口和低频系统工具入口。桌面端为窄左 rail，移动端收敛为顶部横向 rail。
2. 目录侧栏：仅在“项目管理”目录下展示 Project、Feature、Conversation 的层级选择；切到“知识中心”后该侧栏不出现。
3. 目录主内容：根据当前一级目录切换项目工作区或知识中心内容。知识中心使用独立主区域，不与项目管理侧栏或右侧上下文面板混杂。

一级目录切换继续复用现有 `primary-view` 状态模型，但 `view-related` 的语义从“侧栏里隐藏一部分内容”提升为“目录级页面区域隔离”。

## 生效路径

1. `src/web/ui-shell.js` 定义新的首页 DOM 信息架构。
2. `src/web/styles.css` 定义全局 rail、目录侧栏、目录主内容和响应式布局。
3. `src/web/primary-view.js` 和 `src/web/app.js` 保持一级目录切换状态与知识中心加载行为。
4. 本 feature 文档记录需求结论、设计取舍、改动范围和验证结果。

## 风险与决策记录

1. 已决策：本次直接实现可运行首页改版，而不是只提交外部设计稿；原因是现有前端为轻量静态页面，首页信息架构可以通过真实 DOM/CSS 快速形成可预览原型，并减少后续样式还原偏差。
2. 已决策：一级目录采用低占用全局 rail，而不是继续放在项目侧栏中；原因是一级目录是全局范围，不能表现为项目管理的子层级。
3. 已决策：知识中心切换后不显示项目管理侧栏和项目上下文面板；原因是用户明确要求同级目录内容不要混杂展示。

## 范围变更记录

1. 实现过程中发现 `tests/web/workspace-layout-test.ts` 对旧知识中心布局有断言：知识中心仍保留项目侧栏列。该预期与本次“同级目录内容不混杂展示”的目标冲突，因此把测试改为校验知识中心独占目录内容区，并校验全局导航位于项目侧栏之外。
