# F2026052004 B-01 新增问候/闲聊短路规则

## 背景

实际对话中出现误触发：用户在 development stage 的 conversation 中发送 `hi` 问候，系统却启动了完整研发流程（创建 worktree 等）。F2026051101 已设计意图识别规则并通过提示词边界修正高影响动作触发，但缺少对问候/闲聊/无任务指向输入的前置短路判断。

## 目标

- B-01 行动规则中新增一条：收到问候、试探、闲聊或无明确任务指向的输入时，只做简短自然回复，不启动任何工作流、不创建任何资源、不预判用户意图。
- 不确定输入是否有任务指向时，先回复确认，不假设最复杂的场景。

## 非目标

- 不修改 Claude Code 侧的 memory 或 settings 配置。
- 不修改 Snail Shell 运行时代码或新增意图分类器（延续 F2026051101 决策）。
- 不修改会话摘要注入机制。

## 设计

规则插入位置：B-01 行动规则中"行动强度必须匹配用户意图和当前成功标准"之后、"会创建、修改……的高影响动作"之前。

这一位置形成了三层护栏：
1. 行动强度匹配意图（通用判断）
2. **NEW** 无任务指向 → 短路回复（前置拦截）
3. 高影响动作需明确意图（收口检查）

## 改动范围

## 验证

- `npm run check` 通过
- 人工验证：用问候类输入（`hi`、`你好`）验证不触发工作流；用明确任务输入验证正常工作流不受影响

## 风险与决策记录

- 决策：仅通过提示词规则修复，不新增运行时代码。如后续仍出现误触发，再评估是否需要运行时防护。
- 决策：不修改 Claude Code 侧 memory（`feedback_worktree_only.md` 等），本轮只改 Snail Shell 应用层 B-01。
