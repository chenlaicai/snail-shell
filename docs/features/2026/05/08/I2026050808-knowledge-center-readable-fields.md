# I2026050808 知识中心可读字段说明

## 背景

知识中心已经能展示知识内容和系统提示词反哺策略，但当前详情页把标题、内容、原因、来源和反哺策略压成几段大文本。用户看到的是大量内部字段值和枚举值，无法判断每一部分分别代表什么，也不知道 prompt mode、Stage 约束、Snail 约束等表单项应该如何填写。

本 feature 需要从使用者视角重构知识详情展示，让用户能直接理解“这条知识是什么、为什么存在、适用于哪里、是否已经生效、反哺配置怎么填”。

## 目标

1. 在知识详情中按字段展示标题、内容、类型、作用域、状态、治理等级、设计原因和来源，并为每个字段提供简短解释。
2. 将系统提示词反哺状态从内部字段列表改成可读摘要，说明每项配置的作用和当前值。
3. 为 prompt mode 的 `none`、`summary`、`full`、`reference_only` 提供中文含义和适用场景。
4. 为需要用户填写的 Stage 约束、Snail 约束、优先级提供填写说明和示例。
5. 保持当前真实能力边界：只配置已接入运行时的 prompt 注入，不把 Skill、MCP/tool、Checker 伪装成可配置生效方式。

## 非目标

1. 不修改知识数据模型、审批流程或 prompt 注入匹配逻辑。
2. 不新增 Skill、MCP/tool、Checker 的运行时生效链路。
3. 不改变已有知识的默认反哺策略。
4. 不做历史知识迁移。

## 设计

知识详情页采用三层信息结构：

1. 核心知识字段：用户先看到这条知识的标题、正文、类型、作用域、状态和治理等级，并能理解每个字段的含义。
2. 真实反哺状态：展示系统提示词注入是否开启、prompt 模式、Stage/Snail 约束、优先级和使用次数，同时解释“批准不等于使用”。
3. 反哺配置表单：每个输入项都给出“该项控制什么、什么时候需要填、留空代表什么、示例是什么”。

Prompt 模式在 UI 中使用中文标签展示，同时保留提交给 API 的枚举值：

1. `none`：不注入，用于只想保存知识但不让它自动影响 agent 的场景。
2. `summary`：只注入摘要，用于决策、结论和长内容。
3. `full`：完整注入，用于内容短且必须逐字遵守的规则。
4. `reference_only`：作为参考提醒注入，用于偏好、流程和一般规则。

## 生效路径

1. `src/web/knowledge-center.js` 负责渲染字段说明、prompt 模式说明和填写提示。
2. `src/web/styles.css` 负责字段卡片、策略说明和表单提示的布局与可读性。
3. `tests/web/knowledge-center-test.ts` 锁定关键说明文案，避免后续 UI 回退为内部枚举裸展示。

## 改动范围

1. 新增当前 feature 文档。
2. 更新 `src/web/knowledge-center.js`。
3. 更新 `src/web/styles.css`。
4. 更新 `tests/web/knowledge-center-test.ts`。

## 验证

1. 运行 `npm run test -- --filter web`。
2. 验证知识详情包含字段含义说明。
3. 验证 prompt 模式包含中文含义和适用场景。
4. 验证 Stage 约束、Snail 约束和优先级包含填写说明。
5. 验证 Skill、MCP/tool、Checker 仍只作为后续静态产物或运行时注册说明，不作为可编辑配置项。

## 风险与决策记录

当前没有未经确认的问题。

决策记录：本 feature 只改善知识中心的可读性和可填写性，不改变知识反哺运行时语义。原因是用户当前反馈的核心问题是“看不懂字段和选项”，运行时能力边界已经在上一轮 feature 中收敛为 prompt 注入。
