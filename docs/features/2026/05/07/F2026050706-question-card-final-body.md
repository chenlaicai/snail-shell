# F2026050706 问题卡片最终正文渲染

## 背景

当前 Snail 使用 `message-out` 提问时，前端会把流式事件里的结构化内容解析成问题卡片，并显示在“流式过程”中。问题卡片是用户需要直接处理的消息正文，不应作为过程追踪的一部分出现，否则完成态消息的主正文与交互入口不一致。

## 目标

- 完成态 assistant 消息中，`message-out` 问题卡片必须在最终正文区域渲染。
- 流式过程继续用于展示事件追踪、工具调用和中间文本，不承担最终交互卡片入口。
- 保留普通最终文本、普通 `message-out` markdown、流式中间文本和 Boss/user 消息的既有合理展示路径。

## 非目标

- 不改变 `message-out` payload 协议。
- 不调整问题回答提交接口与后端数据模型。
- 不重做消息列表整体视觉样式。

## 设计

完成态 assistant 消息已有 `message_out` 上下文时，前端将最终正文视为规范展示入口。由于消息上下文本身可能只保存 fallback 文本，前端会从消息事件中恢复最后一个 `message-out` 结构化块作为最终正文的语义内容；如果无法恢复结构化块，则继续按上下文文本渲染。

流式事件仍保留完整事件块，但完成态存在 `message_out` 最终上下文时，流式过程中的结构化问题块不再渲染成交互卡片，避免过程区承载最终交互入口。最终正文为空、错误信息或 fallback 文本时也按最终正文呈现，不从过程区恢复问题表单；如果最终答复本应是问题卡片但最终正文没有生成出来，应归因于最终正文生成链路问题，不在本 feature 中通过前端过程区降级处理。

## 生效路径

- `src/web/message-view.js`：构建消息视图时区分过程事件与最终正文语义块。
- `src/web/message-renderer.js`：最终正文可渲染结构化 body blocks。
- `tests/web/message-view-test.ts`：覆盖完成态问题卡片最终正文、过程区不再承载问题卡片，以及既有路径不回归。

## 改动范围

- 新增本 feature 文档。
- 调整 Web 消息视图构建与渲染逻辑。
- 更新 Web 消息视图测试。
- 根据用户补充决策移除过程区问题表单降级语义，明确最终正文才是有效回复来源。

## 验证

- 运行 `npm test`。
- 至少运行 `tests/web/message-view-test.ts` 覆盖本次消息渲染模型。

## 风险与决策记录

用户已确认问题本质：问题卡片不应在流式过程里渲染，应在最终正文渲染。本次按该语义边界修复，不引入新的用户可配置项。

决策：过程只代表过程，最终正文才代表最终有效回复。完成态 `message_out` 消息即使过程事件里曾出现问题块，也不能在过程区渲染可提交表单；否则会把最终为空、错误或 fallback 的消息误呈现为有效问题。若最终答复应该是问题但最终正文没有生成问题卡片，应另行修复最终正文生成逻辑，不在本 feature 范围内用前端降级绕过。

风险：历史完成消息如果最终正文为空、错误或只有 fallback 文本，即使过程区曾有问题事件，前端也不会把过程区问题恢复为表单；这是“最终正文为准”的预期结果。最终正文生成缺失问题卡片属于另一个问题，不在本次修复范围内。

## 范围变更记录

- 初始范围：修复问题卡片从流式过程渲染到最终正文渲染的前端消息视图问题。
- PR 检视后曾补充“最终正文无法恢复时保留过程区表单”的降级路径；用户补充确认该语义错误，已撤销。
- 用户补充后范围收敛：完成态 `message_out` 只以最终正文作为有效回复，不为过程区问题表单提供降级入口；最终正文生成异常另行处理。
