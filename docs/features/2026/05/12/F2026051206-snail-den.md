# F2026051206 Snail Den

## 背景

Snail Shell 需要一个 snail template 池，集中管理所有可用的 agent runtime + model 组合。后续项目管理、知识治理等场景需要从池中选取 template 来分配 snail 实例。当前各 agent 类的 model 硬编码在代码中，缺乏统一的配置入口。

## 目标

- 创建 `config/snail-den.json` 配置文件，定义 snail template 池
- 后端加载配置并暴露 `/api/snail-den` API
- 前端新增 Snail Den 页面，只读展示所有可用 template
- **为其他模块提供"给我一个配好 model 的 snail 实例"的底层服务能力**

## 非目标

- 不修改现有 `.meta/snails.json` 角色定义
- 不修改现有 agent 类的 model 硬编码（保留作为 fallback）
- 不实现 template 的增删改 UI

## 设计

### 配置文件

`config/snail-den.json`：

```json
{
  "snails": [
    {
      "id": "opencode-mimo-v25",
      "name": "OpenCode + Mimo v2.5",
      "runtime": "opencode-cli",
      "model": "my-mimo-plan/mimo-v2.5-pro"
    }
  ]
}
```

字段说明：
- `id`：template 唯一标识
- `name`：显示名称
- `runtime`：agent runtime 标识（`claude-code-cli` | `opencode-cli` | `codex-cli` | `gemini-cli`）
- `model`：模型标识

### 后端

- 新增 `src/snail-den/` 模块，负责加载 `config/snail-den.json`
- 在 `src/api/server.ts` 注册 `/api/snail-den` 路由，返回 template 列表
- **新增 `SnailRuntimeInstance` 接口**：封装 `{ runtime, model, template }`，业务模块通过 `getSnailRuntime()` 获取
- **扩展 `AgentInvocationOptions`**：新增 `model` 字段，agent 优先使用此值，未提供时 fallback 到默认模型

### 底层 agent 对接

- `SnailDen.getSnailRuntime(templateId)` 返回 `{ runtime, model, template }`
- 各 agent（OpenCode/Codex/ClaudeCode/Gemini）支持从 `options.model` 获取模型
- `src/project/collaboration.ts` 注入 `resolveModelForSnail` 方法，从 snail 定义的 `template` 字段获取 model
- agent 类保留硬编码 model 作为 fallback，template 的 model 作为优先覆盖

### 前端

- 新增 `src/web/snail-den-view.js`，渲染 snail den 卡片列表
- 在 `src/web/app.js` 的导航栏新增 "Snail Den" 入口
- 在 `src/web/ui-shell.js` 中预留 snail den 容器

## 风险与决策记录

- snail den 是 template 池，不涉及运行实例管理
- 模块独立，与现有 snail 注册体系无耦合
- 因 app.js 原始非空行数已达到 max-lines 限制（980），新增 snail-den 代码需要同步提取 `buildArchiveCleanupNotice`/`cleanupStepLabel` 到 `archive-cleanup-notice.js`、将 snail-den 状态管理提取到 `snail-den-controller.js`
- **model 覆盖机制**：agent 类保留硬编码 model 作为 fallback，template 的 model 作为优先覆盖
- **可选依赖**：`resolveModelForSnail` 在 `CollaborationDeps` 中设为可选，测试无需配置 Snail Den
