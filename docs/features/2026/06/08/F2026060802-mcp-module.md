# F2026060802 MCP 模块设计：mcp-server + mcp-capability

<!-- [design-time] 以下章节在需求收敛与设计阶段（代码前）完成并锁定 -->

## 背景

V1 的 MCP 模块（`legacy/src/mcp/`）混放了两个完全不同的职责：

1. **本平台作为 MCP server** — JSON-RPC endpoint、协议处理、工具暴露（`set_final_body`）
2. **MCP server 配置管理** — 平台注册 + workspace 文件加载、合并、冲突检测

混放导致理解困难：读代码时不清楚"这个函数是在管理别人的 MCP server，还是在处理自己作为 server 的逻辑"。

V2 genesis（F2026060801）将 MCP 列为非目标。现在正式纳入，按职责拆为两个顶层模块。

## 模块拆分

| 模块 | 目录 | 一句话 |
|------|------|--------|
| MCP Server | `src/mcp-server/` | Snail Shell 自身作为 MCP server，暴露工具给 agent 回调 |
| MCP Capability | `src/mcp-capability/` | 管理平台+workspace 的 MCP server 配置，输出合并结果 |

两个模块无直接依赖，各自独立。

---

## 一、mcp-server

### 业务场景

#### 场景 1：Agent 回调 Snail Shell 设置最终正文

**触发**：Agent 完成分析，调用 `set_final_body` 工具声明最终展示内容

**流程**：
1. Agent 发送 MCP JSON-RPC 请求到 Snail Shell endpoint
2. 解析 `initialize` / `tools/list` / `tools/call` 方法
3. 校验参数，执行工具逻辑
4. 返回 JSON-RPC 响应

#### 场景 2：MCP 协议握手

**触发**：Agent 首次连接，发送 `initialize` 请求

**流程**：
1. 返回协议版本、能力声明、server 信息
2. Agent 发送 `notifications/initialized`（notification，无响应）

### 架构设计

**职责边界**：MCP 协议处理 + 工具暴露。不关心 MCP server 配置管理（那是 mcp-capability 的事）。

**与 V1 差异**：

| 维度 | V1 | V2 |
|------|----|----|
| HTTP 框架 | Express | Hono |
| 入口文件 | `index.ts` 导出一切 | `api.ts` 纯接口 |
| 实现暴露 | 直接导出函数 | `_internal/` 隐藏 |
| 路由挂载 | Express `app.post()` 直接写 | `_internal/routes.ts` Hono 路由适配 |
| 工具实现耦合 | 直接依赖 ConversationStore | 工具 handler 通过 Map 注入，模块自身不依赖存储 |

#### _internal/routes.ts

```typescript
/**
 * Hono 路由挂载。
 *
 * 将 MCP JSON-RPC endpoint 注册到 Hono app。
 * 纯适配层：HTTP 请求/响应 ↔ McpServerService 接口。
 */

import type { Hono } from 'hono';
import type { McpServerService } from '@/mcp-server/api.js';

export function registerMcpRoutes(app: Hono, service: McpServerService, path: string): void {
  app.post(path, async (c) => {
    const body = await c.req.json();

    // 基本校验
    if (!body || typeof body !== 'object') {
      return c.json({ jsonrpc: '2.0', id: null, error: { code: -32700, message: 'Parse error' } }, 400);
    }

    const response = service.handleJsonRpc(body);
    // notification 无响应
    if (response === null) {
      return c.body(null, 204);
    }
    return c.json(response);
  });
}
```

#### _internal/service.ts

```typescript
/**
 * MCP Server 服务实现。
 *
 * 外部禁止 import，通过 mcp-server/api.ts 接口访问。
 * 启动时在 main.ts 中实例化并注入 tool handlers。
 */

import type { McpServerService } from '@/mcp-server/api.js';
import type {
  McpToolDefinition,
  McpToolCallResult,
  McpServerInfo,
  JsonRpcRequest,
  JsonRpcResponse,
} from '@/mcp-server/types.js';
import type { ToolHandler, ToolRegistration } from './tools.js';
import { DEFAULT_TOOLS } from './tools.js';

export class McpServerServiceImpl implements McpServerService {
  private tools: ToolRegistration[] = [];

  constructor(
    private serverInfo: McpServerInfo,
    toolHandlers: Map<string, ToolHandler>,
  ) {
    for (const def of DEFAULT_TOOLS) {
      const handler = toolHandlers.get(def.name);
      if (handler) {
        this.tools.push({ definition: def, handler });
      }
    }
  }

  getServerInfo(): McpServerInfo {
    return this.serverInfo;
  }

  getTools(): McpToolDefinition[] {
    return this.tools.map(t => t.definition);
  }

  handleToolCall(toolName: string, args: Record<string, unknown>): McpToolCallResult {
    const tool = this.tools.find(t => t.definition.name === toolName);
    if (!tool) {
      return { content: [{ type: 'text', text: JSON.stringify({ error: `Unknown tool: ${toolName}` }) }] };
    }
    return tool.handler(args);
  }

  handleJsonRpc(request: JsonRpcRequest): JsonRpcResponse | null {
    const { method, params, id } = request;

    // 缺少 method → 解析错误
    if (!method) {
      return { jsonrpc: '2.0', id: id ?? null, error: { code: -32600, message: 'Invalid Request' } };
    }

    // JSON-RPC 2.0 notification：有 method 但无 id，不需要响应
    if (id === undefined) {
      return null;
    }

    let result: unknown;
    switch (method) {
      case 'initialize':
        result = {
          protocolVersion: '2025-03-26',
          capabilities: { tools: {} },
          serverInfo: this.serverInfo,
        };
        break;
      case 'tools/list':
        result = { tools: this.getTools() };
        break;
      case 'tools/call': {
        const p = params ?? {};
        const toolName = typeof p.name === 'string' ? p.name : '';
        const args = (p.arguments ?? {}) as Record<string, unknown>;
        result = this.handleToolCall(toolName, args);
        break;
      }
      default:
        return {
          jsonrpc: '2.0',
          id: id ?? null,
          error: { code: -32601, message: `Method not found: ${method}` },
        };
    }

    return { jsonrpc: '2.0', id: id ?? null, result };
  }
}
```

## 二、mcp-capability

### 业务场景

#### 场景 1：平台注册 MCP server

**触发**：server 启动，注册内置 MCP server（如 `snail-final-response`）

**流程**：
1. 调用 `registerPlatformServer()` 注册
2. 同名则更新

#### 场景 2：加载 workspace MCP servers

**触发**：构建 ACS 或 UI 请求 MCP server 列表

**流程**：
1. 读取 `.snail/mcp.json`
2. 解析为 `McpServerConfig[]`
3. 与平台级合并，同名冲突则抛 Error

#### 场景 3：UI 展示 MCP server 列表

**触发**：前端请求

**流程**：
1. 获取合并后的 MCP servers
2. 标记哪些是平台内置的（`getPlatformServerNames()`）

### 架构设计

**职责边界**：MCP server 配置的注册、加载、合并。不关心 MCP 协议处理（那是 mcp-server 的事）。

**配置来源**：
- **平台级**：代码注册（`registerPlatformServer()`）
- **workspace 级**：`.snail/mcp.json` 文件

**合并策略**：同名冲突报错，不允许平台和 workspace 同名。

  env?: Record<string, string>;
  /** HTTP transport: MCP endpoint URL */
  url?: string;
  /** 来源：platform 为平台级，workspace 为工作区级 */
  source: 'platform' | 'workspace';

#### _internal/service.ts

```typescript
/**
 * MCP Capability 服务实现。
 *
 * 外部禁止 import，通过 mcp-capability/api.ts 接口访问。
 * 启动时在 main.ts 中实例化。
 */

import fs from 'node:fs';
import path from 'node:path';
import type { McpCapabilityService } from '@/mcp-capability/api.js';
import type { McpServerConfig } from '@/mcp-capability/types.js';

export class McpCapabilityServiceImpl implements McpCapabilityService {
  private platformServers: McpServerConfig[] = [];

  constructor(private workspaceRoot?: string) {}

  registerPlatformServer(config: McpServerConfig): void {
    const existing = this.platformServers.findIndex(s => s.name === config.name);
    if (existing >= 0) {
      this.platformServers[existing] = config;
    } else {
      this.platformServers.push(config);
    }
  }

  listPlatformServers(): McpServerConfig[] {
    return [...this.platformServers];
  }

  listWorkspaceServers(): McpServerConfig[] {
    if (!this.workspaceRoot) return [];
    return loadWorkspaceMcpServers(this.workspaceRoot);
  }

  collectAllServers(): McpServerConfig[] {
    const merged = new Map<string, McpServerConfig>();

    for (const server of this.platformServers) {
      merged.set(server.name, server);
    }

    for (const server of this.listWorkspaceServers()) {
      if (merged.has(server.name)) {
        throw new Error(
          `MCP server name conflict: "${server.name}" is registered by both platform and workspace. ` +
          `MCP server names must be unique across platform and workspace.`
        );
      }
      merged.set(server.name, server);
    }

    return [...merged.values()];
  }

  getPlatformServerNames(): Set<string> {
    return new Set(this.platformServers.map(s => s.name));
  }
}

/** 从 .snail/mcp.json 加载 workspace 级 MCP server */
function loadWorkspaceMcpServers(workspaceRoot: string): McpServerConfig[] {
  const mcpJsonPath = path.join(workspaceRoot, '.snail', 'mcp.json');
  if (!fs.existsSync(mcpJsonPath)) return [];

  try {
    const raw = fs.readFileSync(mcpJsonPath, 'utf-8');
    const parsed = JSON.parse(raw);
    if (typeof parsed.mcpServers !== 'object' || parsed.mcpServers === null) return [];

    return Object.entries(parsed.mcpServers).map(([name, config]) => {
      const c = config as Record<string, unknown>;
      const command = typeof c.command === 'string' ? c.command : undefined;
      const url = typeof c.url === 'string' ? c.url : undefined;
      return {
        name,
        transport: command ? 'stdio' : 'http',
        command,
        args: Array.isArray(c.args) ? c.args as string[] : undefined,
        env: typeof c.env === 'object' && c.env !== null ? c.env as Record<string, string> : undefined,
        url,
        source: 'workspace' as const,
      };
    });
  } catch {
    /** 容错：.snail/mcp.json 解析失败时不阻断启动，降级为无 workspace MCP */
    return [];
  }
}
```

## 两个模块的关系

```
mcp-server/                mcp-capability/
  api.ts                     api.ts
  types.ts                   types.ts
  _internal/                 _internal/
    service.ts                 service.ts
    routes.ts (MCP RPC)
    tools.ts
       │                          │
       ▼                          ▼
server/routes/               server/routes/
  mcp-server.routes.ts         mcp-capability.routes.ts
  (GET /api/mcp-server/*)      (GET /api/mcp-capability/*)
       │                          │
       ▼                          ▼
     UI                           UI
```

- **无直接依赖**：两个模块各自独立
- **协作点在 main.ts**：启动时分别实例化，按需注入
- **数据流向**：
  - `mcp-server`：Agent → MCP JSON-RPC endpoint → service → tool handler → 业务层
  - `mcp-server` UI：前端 → `GET /api/mcp-server/*` → service → 响应
  - `mcp-capability`：平台注册 + workspace 文件 → 合并 → ACS 消费
  - `mcp-capability` UI：前端 → `GET /api/mcp-capability/*` → service → 响应

## 启动时绑定（main.ts）

```typescript
// mcp-server 初始化
import { McpServerServiceImpl } from '@/mcp-server/_internal/service.js';
import { registerMcpRoutes } from '@/mcp-server/_internal/routes.js';

const toolHandlers = new Map<string, ToolHandler>();
toolHandlers.set('set_final_body', (args) => {
  // handler 实现在这里注入，依赖 conversationRepo 等外部资源
  // mcp-server 模块自身不感知这些依赖
  return { content: [{ type: 'text', text: JSON.stringify({ ok: true }) }] };
});

const mcpServer = new McpServerServiceImpl(
  { name: 'snail-final-response', version: '1.0.0' },
  toolHandlers,
);

// 挂载 MCP JSON-RPC endpoint（给 agent 调用）
registerMcpRoutes(app, mcpServer, '/snail-final-response');

// 挂载前端 API routes
import { registerMcpServerApiRoutes } from '@/server/routes/mcp-server.routes.js';
registerMcpServerApiRoutes(app, mcpServer);

// mcp-capability 初始化
import { McpCapabilityServiceImpl } from '@/mcp-capability/_internal/service.js';

const mcpCapability = new McpCapabilityServiceImpl(workspaceRoot);

mcpCapability.registerPlatformServer({
  name: 'snail-final-response',
  transport: 'http',
  url: `http://localhost:${port}/snail-final-response`,
  source: 'platform',
});

// 挂载前端 API routes
import { registerMcpCapabilityApiRoutes } from '@/server/routes/mcp-capability.routes.js';
registerMcpCapabilityApiRoutes(app, mcpCapability);

// ACS 构建时消费
const mcpServers = mcpCapability.collectAllServers();
```

## 待确认项

1. **`set_final_body` 的 handler 实现**：需要写入 message context，handler 内部依赖 `ConversationRepo`。这个依赖关系在 main.ts 注入时解决，mcp-server 模块自身不感知。
2. **McpServerConfig 与 acs/McpServerCapability 的关系**：`mcp-capability/types.ts` 的 `McpServerConfig` 含 `source` 字段，`snail/acs/types.ts` 的 `McpServerCapability` 不含。ACS 构建时需要转换。暂时各自独立，后续统一。
