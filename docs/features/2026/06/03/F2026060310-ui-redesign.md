# F2026060310 [web] UI 重构：两层展示架构

<!-- [design-time] 以下章节在需求收敛与设计阶段（代码前）完成并锁定 -->
<!-- 进入实现阶段后不得单方面修改，如需变更须通过问题卡片向用户提出并确认 -->

## 背景

当前 UI 将 issue 列表放在侧边栏，选择 issue 后直接进入对话。这种结构有两个问题：

1. 缺少 workspace 级别的任务总览——用户无法一眼看到某个 workspace 下所有 issue 的状态分布
2. 侧边栏承载了 issue 列表和导航双重职责，导致空间紧张、层级不清

用户希望改为两层展示：先看 workspace 的任务看板，再进入单个 issue 的对话。

## 目标

### P1 — 两层展示架构

重构 Web UI 为两层展示：

1. **View A：Workspace 任务看板** — 选择 workspace 后，默认展示该 workspace 下所有 issue 的三列看板（待处理 / AI工作中 / 已完成）。中右区域合并为一个完整看板，无左右分割。
2. **View B：Issue 对话** — 点击某个 issue 后，中右区域分为中间主对话区 + 右侧状态栏，展示 issue 的消息流和状态信息。

## 非目标

- 不修改后端 API 或数据模型
- 不改变 issue 的生命周期或状态机
- 不添加新的 issue 状态（保持现有三态：待处理 / AI工作中 / 已完成）
- 不在任务看板中为不同状态做差异化视觉降噪处理

## 设计

### P1 详设

**View A：Workspace 任务看板**

| 区域 | 内容 |
|---|---|
| 左侧 sidebar | 导航模块 + workspace 树（仅 workspace 节点选择，不含 issue 条目） |
| 中间全宽 | 三列看板：待处理 / AI工作中 / 已完成 |

- 看板头部：筛选按钮 + 新增 Issue 按钮（无 tabs，避免与三列分组重复）
- 每张卡片展示：标题、ID、摘要、当前 stage 标签、等待时间
- 三个分组视觉样式一致

**View B：Issue 对话**

| 区域 | 内容 |
|---|---|
| 左侧 sidebar | 导航模块 + workspace 树（当前 issue 高亮），底部"新建 Issue"按钮 |
| 中间 | 主对话区：消息流 + 结构化内容块 |
| 右侧 | 状态栏：Stage Pipeline、Output Artifacts、参与者、Gate Evidence、本阶段要求 |

- 对话区展示真实交互模式：系统通知、用户消息、agent 回复（含 tool call 和 artifact 结构化块）、question card
- 底部 composer 支持 @mention

**状态分组规则**

- 三态分组：待处理、AI工作中、已完成
- 不按紧急程度分组
- AI工作中与待处理互斥——同一 issue 不会同时出现在两个分组中

## 生效路径
