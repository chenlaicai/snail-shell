## 1. 需求背景

### 问题

当前对话界面使用 `@tanstack/react-virtual` 虚拟滚动渲染消息列表，已有粘性底部逻辑（新消息到来时自动滚到底部）。但用户在查看历史消息时，没有快速回到顶部或底部的方式，只能手动滚动。

### 场景

1. **到顶**：用户想查看对话最早的上下文（如 Issue 描述、初始指令）
2. **到底**：用户查看历史后想快速回到最新消息

### 约束

- 虚拟滚动环境下，`scrollToIndex` 比直接操作 `scrollTop` 更可靠
- 一键到顶后，不应触发粘性底部（否则新消息到来会打断用户阅读历史）
- 一键到底后，应恢复粘性底部行为

---

## 2. 设计方案

### 2.1 UI 设计

**位置**：对话区域右下角，两个浮动按钮垂直排列

```
┌─────────────────────────────────────┐
│  消息列表                            │
│  ...                                │
│  ...                                │
│                            ┌───┐    │
│                            │ ↑ │    │  ← 一键到顶
│                            ├───┤    │
│                            │ ↓ │    │  ← 一键到底
│                            └───┘    │
└─────────────────────────────────────┘
```

**显示条件**：
- 消息数量 > 0 时显示
- 到顶按钮：仅当不在顶部时显示（`scrollOffset > threshold`）
- 到底按钮：仅当不在底部时显示（`!wasAtBottom`）

**视觉样式**：
- 圆形按钮，半透明背景，hover 时加深
- 图标：`↑` 和 `↓`（或 chevron 图标）
- 尺寸：32px × 32px
- 位置：右下角，距离边缘 16px

### 2.2 滚动行为

**一键到顶**：
```typescript
virtualizer.scrollToIndex(0, { align: 'start' });
```
- 使用 `scrollToIndex` 确保虚拟滚动正确渲染
- 滚动后设置 `wasAtBottomRef.current = false`，禁用粘性底部
- 用户手动滚到底部或点击"一键到底"后恢复

**一键到底**：
```typescript
virtualizer.scrollToIndex(sorted.length - 1, { align: 'end' });
```
- 滚动到最一条消息
- 设置 `wasAtBottomRef.current = true`，恢复粘性底部

### 2.3 平滑滚动

使用 `behavior: 'smooth'` 实现平滑动画：
```typescript
virtualizer.scrollToIndex(0, { align: 'start', behavior: 'smooth' });
```

> 注意：`@tanstack/react-virtual` 的 `scrollToIndex` 支持 `behavior` 参数，但需要确认版本兼容性。

## 3. 核心业务行为

| # | 条件 | 行为 |
|---|------|------|
| B1 | 用户点击"到顶"按钮 | 滚动到第一条消息，禁用粘性底部。**前置条件**：仅当不在顶部时显示该按钮。**副作用**：到顶后新消息到来不触发任何提示或自动滚动，用户需手动点击"到底"按钮返回 |
| B2 | 用户点击"到底"按钮 | 滚动到最后一条消息，恢复粘性底部。**前置条件**：仅当不在底部时显示该按钮 |
| B3 | 消息列表为空 | 不显示任何滚动按钮 |

**边界行为**：
- 快速连续点击：无需防抖，`scrollToIndex` 天然幂等，多次调用结果一致
- 滚动与点击并发：按钮点击优先，中断当前手动滚动并执行目标滚动
- 按钮层级：按钮浮于消息列表之上，不遮挡输入框或其他交互元素

## 4. 技术约束与依赖

### 4.1 依赖

- `@tanstack/react-virtual` v3.14.3（已安装），支持 `scrollToIndex` 的 `behavior: 'smooth'` 参数
- 无新增依赖

### 4.2 滚动行为规格

- **到顶**：`scrollToIndex(0, { align: 'start', behavior: 'smooth' })`
- **到底**：`scrollToIndex(count - 1, { align: 'end', behavior: 'smooth' })`
- `scrollToIndex` 会自动处理虚拟滚动的 DOM 节点渲染/清理

### 4.3 与现有逻辑的交互

- 滚动位置检测阈值：80px（与现有粘性底部逻辑一致）
- 到顶后设置 `wasAtBottom = false`，禁用粘性底部
- 到底后设置 `wasAtBottom = true`，恢复粘性底部
- 用户手动滚动到底部阈值内时，同样恢复粘性底部

## 6. 开放问题

### Q1: 按钮位置是否需要调整？

当前设计为右下角浮动按钮。备选方案：
- A) 右下角浮动（当前方案）
- B) 消息列表顶部/底部内嵌
- C) 滚动条旁集成

**决策**：采用 A 方案，与其他 IM 应用（Slack、Discord）一致。两位架构师均认可。

### Q2: 是否需要"新消息"提示？

一键到顶后，如果有新消息到来，是否需要显示"新消息"提示条？

**决策**：不在本特性范围内。到顶后新消息到来不触发任何提示或自动滚动，用户需手动点击"到底"按钮返回。

### Q3: 平滑滚动时长

`behavior: 'smooth'` 使用浏览器默认时长（通常 300-500ms）。是否需要自定义？

**决策**：使用浏览器默认值，无需额外配置。两位架构师均认可。
