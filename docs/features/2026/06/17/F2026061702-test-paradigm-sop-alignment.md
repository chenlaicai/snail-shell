# F2026061702 [testing] 测试范式 SOP 对齐：默认不写测试 + 行为契约守护

<!-- [design-time] 以下章节在需求收敛与设计阶段完成并锁定 -->

## 背景

用户在 Snail Shell v2 重构后，要求"全都不写测试"。原因：

1. **历史测试无价值**：v1 的测试代码大部分是实现绑定测试（断言 fetch 参数、内部状态、函数调用次数），重构时全挂但业务逻辑未变
2. **AI 行为问题**：AI 遇到测试挂了，会反过来修改主代码去适配测试代码，颠倒了测试与被测代码的主仆关系
3. **v2 已清理测试**：F2026060901 已移除 v2 的测试代码和测试依赖，等待重新设计架构后再补齐

F2026060701 已建立"行为契约测试"范式，但未明确"什么时候写测试"的准入条件。本次在此基础上增加准入条件，让 SOP 与用户实际要求对齐。

## 目标

调整 SOP 中的测试规范，明确：
- 默认不写测试（当前阶段策略）
- 写测试时必须是行为契约测试
- 测试场景来源是 feature spec 的核心业务行为列表
- 无测试时的验证方式

### P1 — SOP 调整

- 修改 `development#developer.handbook.md`：增加"测试编写准入条件"章节
- 修改 `docs/README.md`（feature 模板）："核心业务行为"章节改为可选
- 修改 `review#reviewer.handbook.md`：测试质量检查改为"有测试时检查，无测试时不阻塞"
- 修改 `.meta/prompts/reference/测试.md`：同步更新准入条件

### P2 — 清理 v1 测试

- 删除 `v1/src/web/tests/` 目录下的实现绑定测试
- 删除 v1 的测试依赖（如有）

## 非目标

- 不删除 F2026060701 建立的行为契约测试范式——它是未来写测试时的规范
- 不禁止所有测试——只是明确"默认不写，写了就必须是行为契约测试"
- 不引入新的测试框架

## 设计

### 核心概念：测试编写准入条件

**准入条件**（满足以下条件之一时才编写测试）：
1. 用户明确要求"写测试"
2. 修复已知 bug 后补写回归测试（必须关联 bug 描述）
3. feature spec 的"核心业务行为"章节非空且用户确认需要测试

**不满足以上条件时，不得自行编写测试。**

### P1 详设：SOP 调整

**development#developer.handbook.md 修改**：

在"核心业务行为列表使用规则"章节前，增加"测试编写准入条件"章节：

```markdown
### 测试编写准入条件

**默认策略**：当前阶段不主动编写测试。只有满足以下条件之一时才编写测试：
1. 用户明确要求"写测试"
2. 修复已知 bug 后补写回归测试（必须关联 bug 描述）
3. feature spec 的"核心业务行为"章节非空且用户确认需要测试

不满足以上条件时，不得自行编写测试。

**无测试时的验证方式**：
- `npm run build` + `npm run check`（编译通过）
- `npm run lint`（代码规范）
- 人工验证核心业务流程（在 PR 中说明验证方式）
```

**docs/README.md 模板修改**：

"核心业务行为"章节改为可选：

```markdown
## 核心业务行为（可选）

本 feature 涉及的核心业务行为列表。每条行为是"当 X 时，应该 Y"的形式，断言的是外部可观测行为（输入/输出/状态变化/错误），不是内部实现。

**填写条件**：只有用户明确要求写测试时才填写此章节。不填写时，测试场景来源为开发者判断 + 审查者把关。
```

**review#reviewer.handbook.md 修改**：

测试质量检查改为：

```markdown
12. 测试质量（有测试时检查，无测试时不阻塞）：
    - 测试是否对应 feature spec 中的核心业务行为？
    - 断言的是外部可观测行为，还是内部实现？
    - 如果删除测试中的 mock，断言是否仍然成立？
    - mock 仅作为隔离手段，不作为断言依据
    - 无测试时：不阻塞 PR，但需确认验证方式已说明
```

### P2 详设：清理 v1 测试

删除 `v1/src/web/tests/` 目录下的所有测试文件：
- `api.test.ts`（断言 fetch 参数）
- `conversationStore.test.ts`（断言内部状态）
- `StageActions.test.tsx`（断言 UI 文案）
- `WorkspaceBoard.test.tsx`（断言渲染结果）
- 其他测试文件

### 设计决策

| # | 决策点 | 正方论点 | 反方论点 | 最终决策 | 决策依据 |
|---|-------|---------|---------|---------|---------|
| D1 | 默认不写测试 | 用户明确要求；v1 测试无价值 | 测试是质量保障 | 默认不写，用户要求时写 | 用户决策优先 |
| D2 | 是否保留行为契约测试范式 | 未来可能需要写测试 | 当前不需要 | 保留 F2026060701 规范，作为写测试时的标准 | 有规范比没规范好 |
| D3 | 是否删除 v1 测试 | v1 测试是实现绑定测试 | 可能有参考价值 | 删除，v2 会重新设计 | 避免误导 |
