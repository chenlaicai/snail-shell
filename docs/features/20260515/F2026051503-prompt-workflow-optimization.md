# F2026051503 研发者/检视者工作流程提示词优化

## 背景

架子优先机制（F2026051501）重构了提示词注入结构，但 S-03（研发者手册）和 S-04（检视者手册）的内容仍沿用旧的"长步骤列表"组织方式。实际使用中发现两个核心问题：

1. 研发者基本不新建 worktree 来干活 — worktree 规则埋在步骤 1.2，AI 容易跳过或忽略
2. mention 机制频繁失效 — 只说了"用 message-out mention"，没有给出具体命令模板，AI 要么用自然语言 `@` 代替，要么不知道怎么调用

根本原因：工作流程以"编号步骤"组织，关键阻塞操作和普通建议混在一起，AI 无法区分硬性前置条件和可选建议；worktree 被定位为"研发者的环境准备步骤"，但实际上它是所有非只读操作的通用前置条件（包括检视者读取代码）。

## 目标

1. worktree 从 S-03 的开发步骤提升到 B-01 作为所有 Snail 的通用操作前提
2. 工作流程从"编号步骤"改为"阶段 + 门控（GATE）"结构，关键阻塞操作显式标记
3. mention 命令模板内联到工作流步骤中，减少 AI 需要额外读取 SKILL.md 的不确定步骤
4. 检视者工作流程增加 worktree 进入步骤

## 非目标

- 不修改 Frame（F-01~F-04）的注入条件
- 不修改 S-01、S-02、S-05、S-06、B-02、B-03
- 不改变提示词治理规则
- 不改变职责原则内容

## 设计

### B-01 身份与责任契约

- **行动规则**新增通用 worktree 前置条件：所有非只读操作必须在隔离 worktree 或用户明确指定的目录中执行
- **结构化消息边界**新增 message-out 标准调用模板（一行命令，不是 SKILL.md 全文复制）
- **禁止项**替换原有 worktree 条目为更精简的通用约束

### S-03 研发者手册

Development 工作流程重构为 4 个阶段：
- 阶段一：环境准备（4 个 GATE：origin/main 最新、worktree 已创建、feature 文档已检查、背景已追溯）
- 阶段二：需求收敛与设计（步骤 5~10）
- 阶段三：实现（步骤 11~15）
- 阶段四：验证与提交 PR（步骤 16~22）
- Feature 收口（步骤 23~25）

Review 工作流程重构为 3 个阶段：
- 阶段一：请求检视（2 个 GATE + message-out 命令模板内联）
- 阶段二：分析与处理检视意见（步骤 4~7）
- 阶段三：Review 收口（步骤 8~13）

步骤编号从原 26 号归位为 10，全链路连续编号。

### S-04 检视者手册

检视工作流程重构为 4 个阶段：
- 阶段一：准备与上下文加载（4 个 GATE：进入 worktree、PR 基于最新 main、分支属于当前 feature、feature 文档编号合规）
- 阶段二：判断检视重点（步骤 7~8）
- 阶段三：对抗性检查（步骤 9~18）
- 阶段四：问题报告与对话回传（步骤 19~23，message-out 命令模板内联）

复检流程新增步骤 0：重新进入 feature 的 worktree。

## 生效路径

规则通过 `.meta/prompts/prompts/` 下的提示词文件生效，经 F-01 架子按条件注入到 Implementation Snail 和 Acceptance Snail 的系统提示词中。

## 改动范围

- `.meta/prompts/prompts/B-01-身份与责任契约.md` — 行动规则、结构化消息边界、禁止项
- `.meta/prompts/prompts/S-03-研发者手册.md` — Development 工作流程、Review 工作流程、自检清单
- `.meta/prompts/prompts/S-04-检视者手册.md` — 检视工作流程、复检流程、自检清单

## 验证

1. 检查 S-03、S-04 的 frontmatter 格式符合 `docs/core/prompt-system-structure.md` 规范
2. 检查自检清单编号与工作流程步骤对应
3. 检查 B-01 的 worktree 规则与 S-03/S-04 的 worktree 步骤不重复（B-01 定义通用约束，S-03/S-04 定义具体操作）
4. `npm run check` 确保无意外影响

## 风险与决策记录

- B-01 新增了 message-out 命令模板，与"能力引用边界"（只引用能力边界，不复制 skill 正文）存在一定张力。决策：一行调用命令属于调用入口，不是 skill 正文复制，可接受。
- S-03 步骤编号重排（原 26→10），如果有其他地方引用了旧编号需要同步更新。经检查，无外部引用。
