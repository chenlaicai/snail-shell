# F2026052107 提示词更新：正确才是真正的速度

## 背景

PR 236（任务锚与反目标机制）通过外部约束对抗 AI 的"目标替换"——用 [HARD] 规则、任务锚和场景细则来拉长"表面修复"的路径。但有一个维度尚未直接处理：**AI 的隐式优化目标天然倾向于"可即时验证的表面成功"**，而现有规则都是"不准这样做"的外部约束，没有从认知层面对齐 AI 的内在动机。

核心洞察：不是对抗 AI 的"追求快"，而是重新定义"快"——如果 AI 内化了"做对才是快"，那它追求快的冲动就不再与追求对冲突，而是变成了同一个目标。这是"框架重构"（reframing）而非"增加约束"。

同时，两个具体设计场景缺乏明确的"先对齐再动手"流程规则：
- UI 设计：AI 倾向于直接写组件代码，跳过视觉效果确认
- 数据模型设计：缺乏可视化工具来让用户和 AI 达成共享理解

## 目标

- 在 B-01 `<guideline>` 新增"正确才是真正的速度"原则，作为计划与拆分规则的认知基础
- 在 S-03 "需求收敛与设计"新增 UI 设计流程规则：先画 HTML 效果图，与用户确认后再编码
- 在 S-03 "需求收敛与设计"新增数据模型设计规则：使用 Mermaid 图达成共识

## 非目标

- 不改变现有规则的语义和强制执行层级
- 不新增提示词模块
- 不修改 developer-handbook skill

## 设计

### 三层改动的定位

```
B-01 <guideline> 计划与拆分规则
  ├─ [新增] 认知基础："快做错一百次，不如慢做对一次——正确才是真正的速度"
  └─ [既有] 单向前进、一步到位、避免过渡方案（不变）

S-03 <protocol> 需求收敛与设计
  ├─ [新增] UI 设计流程：HTML 效果图 → 用户确认 → 编码
  ├─ [新增] 数据模型设计：Mermaid 图 → 用户与 AI 共识
  └─ [既有] 设计规则（不变）
```

### 设计决策

**"做对才是快"放 B-01 而非 S-03**：这是通用认知原则，不仅适用于研发者角色。所有角色在制定计划时都应内化"正确=速度"的认知。

**UI 和数据模型规则放 S-03 而非 B-01**：这两个是研发者角色在设计阶段的具体操作流程，属于角色规则层而非通用原则层。

**表述聚焦"正确"而非"慢"**："慢"不是目标，"正确"才是。不把焦点放在"慢慢做"上——因为那可能被误解为"无休止分析"。

## 验证

- B-01 和 S-03 提示词文件格式正确，YAML frontmatter 完整
- 新增规则与现有规则无冲突、无重复：
  - B-01 "做对才是快" 是计划与拆分规则的认知基础，不与具体规则冲突
  - S-03 UI 设计流程补充了已有的 "面临 UI/UX 设计时检索网上优秀实践" 规则——前者说"查什么"，后者说"先确认再动手"
  - S-03 Mermaid 规则是全新领域，无冲突可能
- 提示词评估样本：判断为本次不需要新增。原因：
  - "做对才是快"是认知框架重构，效果体现在多步行为模式中，不适合单次 request/response 评估
  - UI/Mermaid 规则是设计流程指导，效果体现在工作流中而非单次响应
  - 后续如发现行为偏差再补评估样本

## 风险与决策记录

- **过度谨慎风险**："慢做对一次"可能被误解为"无休止分析"。B-01 现有的"单向前进"规则（每一步直接推进到目标状态）已在防范——"做对"不等于"不做"，而是"不走需要折返的错路"。如果评估样本中出现明显的过度分析模式，需要调整表述，强调"一步到位"而非"反复推敲"。
- **Mermaid 图的实际效果**：Mermaid 图是否真的能帮助达成共识取决于图的清晰度和用户的 Mermaid 阅读习惯。作为 [STD] 规则（非 [HARD]），AI 应根据实际情况判断图是否必要——简单的单表模型用文字描述即可。
