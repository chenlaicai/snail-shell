# F2026051001 AI 上下文一致性判断

## 背景

用户在另一个 feature 中误发“pr145已合入；但我突然想到另外一点”后，Snail 没有先判断该消息与当前上下文是否一致，而是无条件继续执行。这个反应暴露的问题不是单纯“用户权威不能免判断”，而是 AI 面对突兀输入时缺少上下文一致性校验：用户消息、历史摘要和当前 stage 之间可能存在语义断裂，不能因为文本看起来像任务指令就直接推进。

PR #144 已合入并新增 `P0004-AI判断与责任契约`，其中已覆盖输入可信度、独立判断、问题层级、有边界主动性和语义验收。但现有规则还没有明确要求 AI 在行动前判断“新输入是否属于当前 project / feature / stage / conversation 的有效延续”。因此需要继续补充 base 判断契约，要求 AI 对上下文错位保持疑惑并先查证或提问。

## 目标

1. 在 `ai.base.system` 中补充上下文一致性判断规则，要求 AI 面对突兀、跨 feature、跨 PR、跨 stage 或与当前目标不连贯的输入时，先判断语义关联和有效归属。
2. 明确不能把用户新消息的表面可执行性当作上下文有效性证明；如果消息可能发错位置、引用对象不明或与当前工作流状态冲突，应先说明不一致并查证或提问。
3. 同步 `AGENTS.md` 的通用原则，保持仓库规则线与 `.meta/prompts/` 双线生效一致。
4. 更新 prompt 资产测试，锁定新增 base 契约，避免后续提示词重构时丢失。

## 非目标

1. 不修改已合入的 `docs/features/20260509/F2026050906-ai-base-judgment-contract.md` 历史记录。
2. 不改变 Snail Shell 的 stage 流程、mention 协议、历史查询机制或知识候选流程。
3. 不新增跨 conversation 自动路由能力；本次只约束 AI 在当前输入与上下文不连贯时的判断和提问行为。
4. 不要求所有轻微话题切换都提问；只有归属、事实或下一步行动存在真实不确定时才需要暂停直接执行。

## 设计

本问题属于所有 Snail 都可能遇到的底层判断缺陷：用户、历史消息、工具输出或注入上下文之间可能互相冲突，AI 必须先判断它们是否构成当前任务的有效输入。该规则不绑定单一角色或 stage，因此归入 `P0004`。

新增规则应强调三个边界：

1. 上下文归属：新输入需要能解释为当前 project、feature、stage、conversation 和已有目标的延续，不能只因用户说了可执行内容就默认归属当前任务。
2. 断裂处理：发现跨 feature、跨 PR、跨 stage、引用对象不明、状态冲突或语义不连贯时，应先暴露疑惑，查证历史或提出真实待决策问题。
3. 正常切换保护：如果用户明确提出新的目标，且与当前状态不冲突，AI 可以继续处理；规则针对的是上下文有效性不足却被机械执行的情况。

## 风险与决策记录

已接受的设计决策：本次反馈应作为新 feature 记录，而不是修改 PR #144 的历史 feature 文档。原因是 PR #144 已合入，历史 feature 文档不应被后续需求追写。

已接受的设计决策：上下文一致性判断归入 `ai.base.system`，而不是某个 stage playbook。原因是该缺陷发生在所有 Snail 接收输入并选择行动前的基础判断链路。

已接受的设计决策：规则不应要求任何话题变化都停下来提问。明确的新目标可以直接处理；只有当前输入与现有上下文无法合理衔接、事实不足或行动归属存在真实不确定时，才应先查证或提问。
