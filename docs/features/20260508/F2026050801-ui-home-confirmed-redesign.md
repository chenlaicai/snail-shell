# F2026050801 首页确认版 UI 重设计

## 背景

用户希望首页重设计先通过可看原型收敛，再按确认样式实现。前一轮直接提交真实代码 PR 偏离协作流程，已关闭并废弃。本轮已通过静态 HTML 原型确认方向：页面采用左、中、右三栏；左侧顶部固定系统图标和英文名，一级目录收纳在品牌下方；Project、Feature、Conversation 和知识中心子目录均以统一目录树呈现；中间区域去掉重复顶部信息，只承载当前目录的主内容；右侧展示当前目录的上下文。

## 目标

1. 将首页改为确认后的三栏结构：左侧目录树、中间主内容、右侧上下文。
2. 系统名称只保留图标和英文名 `Snail Shell`。
3. 一级目录位于品牌下方，支持项目管理与知识中心切换，并可收纳。
4. 项目管理目录中以目录树表达 Project → Feature → Conversation 层级，避免多个同级卡片堆叠造成视觉噪声。
5. 知识中心目录独立展示知识相关导航、列表、详情和治理上下文，不混入项目工作区内容。
6. 中间项目工作区移除重复顶部标题区，保留消息流、流式过程、最终正文和发送区域。
7. 保留真实业务术语，不为减少重复而改写概念名称。

## 非目标

1. 不改变后端 API、数据库 schema 或知识治理模型。
2. 不把静态 HTML 原型作为长期正式文档入口随 PR 提交。
3. 不重做消息渲染协议，只调整页面布局与承载区域。
4. 不改变 Feature、Stage、Conversation 的创建、推进、归档行为。

## 设计

HTML 原型 `docs/prototypes/ui-home-v1.html` 是本轮设计输入，用于收敛视觉方向；正式仓库不提交该临时原型文件。实现时将其设计转换为真实页面结构：

1. 左侧：固定品牌区、一级目录切换区、目录树区。
2. 项目管理目录树：Project 为根节点，Feature 为二级节点，Conversation 为叶子节点；只有最终选中的叶子节点显示背景强调，父级只保留展开层级。
3. 知识中心目录树：知识中心为根节点，知识库、待审批、当前项目知识等为目录节点；使用真实业务术语，不为去重改名。
4. 中间：项目管理时直接显示消息流和 composer；知识中心时显示知识列表与详情。
5. 右侧：项目管理时显示 Stage、Participants、Deliverables；知识中心时显示治理上下文与操作。

## 生效路径

1. `src/web/ui-shell.js` 定义新的首页 DOM 信息架构。
2. `src/web/styles.css` 定义确认版三栏、目录树、消息区、知识中心和响应式样式。
3. `src/web/app.js` 负责渲染项目目录树、绑定折叠交互、切换知识中心上下文。
4. `tests/web/workspace-layout-test.ts` 校验新的布局不变量。
5. 本 feature 文档记录需求结论、取舍和验证结果。

## 风险与决策记录

1. 已决策：静态 HTML 原型只作为设计输入，不随正式 PR 提交到 `docs/`。原因是它服务本轮视觉收敛，后续长期事实应由 feature 文档和真实实现承载，避免一次性原型成为长期维护入口。
2. 已决策：后续大视觉调整继续先改 HTML 原型，小范围实现细节可直接在 PR 上调整。原因是大方向需要用户先看，小修则不应额外制造原型/实现双维护成本。
3. 已决策：不能为减少重复而改写业务术语；重复信息通过信息架构和区域职责调整解决。
