# 演进执行者工作流程

## 演进项创建参考（按需）

治理对话中如需创建新演进项，使用 `snail-evolution` MCP 的 `create_candidate` tool。关键字段速查：
- `title`（必填）：候选标题
- `content`（必填）：可长期复用的正文
- `workspace_id`（必填）：所属 workspace id
- `tags`（可选）：标签列表
- `metadata`（可选）：结构化补充信息

副作用：一次调用会原子性创建 evolution_item + issue + stage + conversation 4 条记录。

## Gotchas（必读）

- **演进项不能自动生效**：候选只进入治理队列，必须经治理对话后才可能反哺 prompt、skill、工具、检查器或知识库。
- **不要把演进项写入 stage 正式产物**：演进项的治理结论独立于当前 issue 的阶段产物。
- **PR 不由你直接创建**：治理对话只记录结论和去向。如需创建 PR，与用户协商后由用户通过工作区推进。
- **不要盲目接受来源标记**：候选的标题、标签由来源系统提供，你需基于事实判断是否正确，必要时建议修正。
- **不要为缺少长期复用价值的内容创建候选**：一次性任务状态、普通进度汇报、工具日志不值得治理。
- **自动创建的条目可能是误触发**：agent 自动识别反馈信号时可能误判。裁决时如发现实际不构成反馈，应标记为"误触发"并关闭，不产出任何系统变更。

## 工作流程索引

1. **入口校验** — 验证演进项来源和事实。详见 `references/workflow.md`。
2. **查重** — 通过对话上下文和用户确认判断重复/相关/可合并（当前无专用搜索 tool）。详见 `references/workflow.md`。
3. **分析** — 评估内容、来源、类型和范围。详见 `references/workflow.md`。
4. **裁决** — 决定治理去向。详见 `references/artifact-decision.md`。
5. **产物处理** — 如需 PR，与用户协商后由用户推进。详见 `references/workflow.md`。

## 关键约束

- 裁决结果必须与用户确认后才能回写，不得单方面执行
- 一个演进项对应一个主要去向，涉及多个去向时拆分治理
- 裁决去向通过 `tags` 和 `metadata` 回写，不直接修改演进项内容

## 完成标准

- evo-01：演进项来源和事实已查证
- evo-02：裁决去向已回写（通过 evolution API 更新 `tags` 和 `metadata`）
