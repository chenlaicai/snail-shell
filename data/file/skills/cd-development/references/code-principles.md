# 代码仓库完美状态原则

## 核心约束

代码仓库不允许存在兼容性桥接代码。

### 具体规则

- **不允许** `if oldFormat then migrate` 类型的兼容性代码
- **不允许** 自动迁移脚本（除非是数据库初始化）
- **数据库 schema** 只允许 `CREATE TABLE IF NOT EXISTS`，不允许 `ALTER TABLE`
- 新功能必须在"完美状态"下实现——不需要兼容旧状态

### 为什么

兼容性桥接代码会：
1. 增加代码复杂度和维护成本
2. 产生"兼容性债务"——越积越多，最终无法清理
3. 掩盖设计问题——如果需要兼容，说明设计没有收敛

### 唯一例外

数据库初始化脚本中的 `CREATE TABLE IF NOT EXISTS` 是唯一允许的兼容性代码，因为数据库状态无法通过 git 管理。
