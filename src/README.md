# Architecture Decisions

## 1. 严禁创建 shared 这种上帝类

**决策**: 禁止创建 `shared/` 这种大而全的共享模块。

**原因**:
- 上帝类导致所有模块都依赖它，违反单一职责
- 类型修改影响范围不可控，牵一发动全身
- 阻碍模块独立演进和测试

**做法**:
- 类型定义在使用它的模块内（如 `workspace/types.ts`）
- 多模块共用的类型，明确归属到某个模块，其他模块依赖该模块
- 工具函数同理，跟随业务归属，不搞大杂烩

## 2. 依赖倒置：db/ 是基础设施层

**决策**: 各原子模块定义接口，`db/` 统一实现。

**结构**:
```
workspace/
  types.ts           # Workspace 类型定义
  repository.ts      # 接口定义 (如 WorkspaceRepository)

db/
  workspace.ts       # 具体实现 (SQLite 操作)
```

**原则**:
- 原子模块只定义接口，不关心存储细节
- `db/` 实现所有模块的存储接口，是唯一的数据库访问层
- 业务层依赖接口，不依赖实现
