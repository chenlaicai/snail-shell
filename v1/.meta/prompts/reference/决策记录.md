# 决策记录规范

本文件定义决策记录的通用规则，各 handbook 引用本文件。

## 决策记录要求

当检视过程中发现设计问题或需要决策时，必须记录到 Feature 文档的"关键决策记录"章节：

- 开发者发现设计问题并通过问题卡片升级时，记录问题和决策过程
- 审查者提出设计改进建议并被采纳时，记录建议和采纳理由
- 开发者和审查者对实现方案有分歧时，记录分歧点和最终决策

**MUST**：
- 发现问题的人必须记录到 Feature 文档
- 做出决策的人必须确认记录的准确性
- 开发者和审查者必须对决策记录达成一致

**MUST NOT**：
- 不得跳过决策记录
- 不得记录不准确的决策
- 不得跳过一致性检查

**一致性检查的具体步骤**：
1. 开发者和审查者共同检查决策记录
2. 确认记录内容与实际讨论一致
3. 如果发现不一致，重新讨论并更新记录
4. 如果无法达成一致，升级到用户决策
