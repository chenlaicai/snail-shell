# PR 评论签名模板

## 适用范围

本模板适用于开发者和审查者写入 GitHub PR 的普通评论，包括检视意见、检视意见处理结论、复检请求、复检结论和仍需对方响应的说明。

本模板不适用于 message-payload 结构化消息。message-payload 的责任归属和路由由 payload 中的消息元数据与 mentions 字段承担。

## 模板

开发者 PR 普通评论：

```markdown
<评论正文>

by 开发者（<Snail 名称>）
```

审查者 PR 普通评论：

```markdown
<评论正文>

by 审查者（<Snail 名称>）
```

## 规则

1. `<评论正文>` 是实际评论内容，不是需要原样保留的占位文本。
2. `<Snail 名称>` 使用系统提示词中"当前 Snail 名称"注入的值（如 `Claude Code Stateful + Sonnet`）。该值由系统自动注入，不得自行猜测或构造。
3. 签名行必须是评论最后一行，格式为 `by <角色>（<Snail 名称>）`。
4. 评论正文与签名行之间必须保留一个真实 Markdown 空行。
5. 签名不得与正文挤在同一行，不得出现在非末行位置。
6. PR 评论必须使用真实 Markdown 换行，不得把 `\n\n` 当作字面文本写入评论。

## 身份获取指引

**角色身份获取**：
- 签名中的 `<角色>` 必须从系统提示词注入的当前阶段角色上下文获取
- 系统提示词会明确注入当前角色实例名称（如"你是开发者"或"你是审查者"）
- 不得自行猜测角色身份，不得使用历史记忆中的角色信息

**Snail 名称获取**：
- `<Snail 名称>` 从系统提示词中"当前 Snail 名称"注入的值获取
- 如未注入，不得猜测或构造，应使用通用标识（如"Snail"）

**身份认知原则**：
- 签名是身份认知的外在表现，必须严格遵循
- 不确定身份时，优先从系统提示词获取，而非猜测
- 签名不统一反映了身份认知问题，必须严肃对待

## 示例

```markdown
已处理全部检视意见，重新运行 `npm run test` 通过，申请复检。

by 开发者（Claude Code Stateful + Sonnet）
```

```markdown
复检通过，当前没有待处理问题，可以等待用户合入。

by 审查者（OpenCode Stateful + GPT-5.5）
```
