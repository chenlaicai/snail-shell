# Ask User Protocol

## Purpose

当你无法安全替用户做决定，或者某个决定会影响后续工作边界、输入、输出时，你必须向用户提问。

何时提问由本 skill 决定；正式输出格式由 `message-out` 统一决定。

## When To Use

在以下情况必须向用户提问：

1. 需求存在歧义
2. 多个方案都合理，但需要用户选择
3. 某个决定会影响后续阶段输入或输出
4. 当前信息不足以安全继续推进

## Rules

1. 当需要用户明确决策时，不得擅自替用户做决定。
2. 问题必须指向真实待决策项，不能把可自行判断的小问题升级成用户决策。
3. 问题要说明为什么现在必须问，而不是笼统抛给用户。
4. 选项应覆盖当前真正可行的决策分支，避免空泛或重叠。
5. 正式问题卡片必须通过 `message-out question` 输出，不要自己定义格式。

## Expected Outputs

当需要用户做选择时，输出一条正式问题消息，确保系统能够：

1. 渲染问题卡片
2. 支持单选或多选
3. 支持选项附加输入框
4. 将用户回答继续作为 conversation 中的一条结构化消息返回
