# 知识治理 — 参考约束

## API 回写字段映射

[STD] 治理完成后通过知识治理 PATCH API 回写，字段取值：
- `entry_check_status`：`entry_check_passed` | `entry_check_closed` | `deferred` | `merged`
- `dedupe_status`：`unique` | `duplicate` | `related` | `merged`
- `scenario_type`：`negative_feedback` | `new_knowledge_review`
- `disposition_status`：`conclusion_only` | `pr_open` | `pr_merged` | `landed` | `reference_only` | `merged_or_superseded` | `closed` | `deferred`
- `artifact_type`：`conclusion_only` | `system_prompt_pr` | `skill_pr` | `user_manual_pr` | `code_or_checker_pr` | `merge_or_supersede_record` | `knowledge_library_entry`

## 产物类型决策

[STD] 根据裁决去向选择产物类型：
- 无需长期产物 → `conclusion_only`
- 需要修改系统提示词 → `system_prompt_pr`
- 需要新增/修改 skill → `skill_pr`
- 需要更新用户手册 → `user_manual_pr`
- 需要代码或检查器变更 → `code_or_checker_pr`
- 需要合并或取代已有知识 → `merge_or_supersede_record`
- 需要沉淀为知识库条目 → `knowledge_library_entry`（使用 knowledge-library skill 的 create 模式写入）

## PR 创建边界

[STD] 治理对话只记录结论和去向。如需创建系统提示词、skill、文档或代码 PR，与用户协商后由用户通过项目推进对话完成，知识执行者不直接创建 PR。

## 查重与关联知识

[STD] 在查重阶段发现相似知识时：
- 完全重复 → `dedupe_status = duplicate`，建议关闭当前候选或合并
- 相关但不重复 → `dedupe_status = related`，在 `related_knowledge_ids` 中记录关联
- 可合并 → `dedupe_status = merged`，说明合并目标和合并后内容

## 来源标记校验

[STD] 候选知识的标题、类型、作用域由来源系统提供。知识执行者需基于事实判断这些标记是否正确，必要时在结论中建议修正。不要盲目接受来源系统的标记。
