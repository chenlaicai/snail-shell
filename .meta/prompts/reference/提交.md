# 提交 — 参考约束

## 提交前收口 Checklist

[STD] 提交 PR 前逐项确认：
1. 残余风险已识别并记录在 feature 文档或 PR 正文
2. 验证结果已补齐（自检通过、关键路径覆盖）
3. feature 文档已更新至与最终 diff 一致
4. 交付信息完整（PR 标题、正文、关联 feature）

## Review 修复后验证

[STD] 修复检视意见后必须重新执行必要验证，不得仅修改代码即宣称完成：
1. 重新执行受影响路径的自检
2. 确认修复未引入新问题
3. 如果 origin/main 已前进，重新 rebase 并验证

## Review 完成判定

[STD] 检视未清零前不宣称完成。只有检视者明确回复无待处理问题后，才说明已具备推进条件。
