# 演进治理 — 参考约束

## 演进项创建

[STD] 通过 evolution-candidate skill 创建演进候选，字段：
- `title`：候选标题（必填）
- `content`：可长期复用的正文（必填）
- `project_id`：所属 project id（必填）
- `tags`：标签列表，用于分类和检索（可选）
- `metadata`：结构化补充信息，JSON 字符串（可选）

候选只进入治理队列，不自动生效。必须经治理对话后才可能反哺 prompt、skill、工具、检查器或知识库。

## 产物类型决策

[STD] 治理裁决去向通过 `tags` 和 `metadata` 记录：
- 无需长期产物 → 仅记录结论
- 需要修改系统提示词 → tag: `system-prompt`
- 需要新增/修改 skill → tag: `skill`
- 需要更新用户手册 → tag: `user-manual`
- 需要代码或检查器变更 → tag: `code`
- 需要沉淀为知识库条目 → 使用 knowledge-library skill 的 create 模式写入

## PR 创建边界

[STD] 治理对话只记录结论和去向。如需创建系统提示词、skill、文档或代码 PR，与用户协商后由用户通过项目推进对话完成，演进执行者不直接创建 PR。

## 查重与关联知识

[STD] 在查重阶段发现相似演进项时：
- 完全重复 → 建议关闭当前候选或合并
- 相关但不重复 → 在 `metadata.related_items` 中记录关联
- 可合并 → 说明合并目标和合并后内容

## 来源标记校验

[STD] 候选知识的标题、标签由来源系统提供。演进执行者需基于事实判断这些标记是否正确，必要时在结论中建议修正。不要盲目接受来源系统的标记。
